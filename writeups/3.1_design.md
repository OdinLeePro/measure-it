## Decision and Model Suitability
The model routes a support ticket and proposes a refund amount:

| Path       | Decision                                 |
| :--------- | :--------------------------------------- |
| `answer`   | Information only                         |
| `refund`   | Up to $50, no approval                   |
| `hold`     | Over $50 through $200, approval required |
| `escalate` | Over $200, unclear, or uncertain         |

The model interprets ticket language / contents, but code is used to validate amounts and enforce approval limits. Unclear cases are sent to a person, i.e. customer support staff. This ensures that the model can't authorize dangerous-sized refunds on its own, nor can it fall victim to prompt-injection attacks.

The results show that the current system doesn't quite meet the proposed targets for routing and refund safety, so there is still work to be done. However, the results are adequate for the purposes of this project's writeups. At the moment, the most serious gap is in refund safety, where unauthorized self-service refunds are not consistently blocked. Specifically, that check passed only $\frac{54}{70}$ to $\frac{55}{70}$ of decisions in each run. Ticket format was not a problem in these runs, but a valid response format does not make an incorrect route safe.
